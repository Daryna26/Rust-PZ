1. Rust підтримує і однопотокове, і багатопотокове програмування. За замовчуванням код синхронний, але Rust має повноцінну підтримку асинхронності через async/await без вбудованого runtime.
2. Rust не має важкого runtime, як Java чи Go, і не використовує garbage collector. Керування памʼяттю відбувається на етапі компіляції через ownership, borrowing і lifetimes.
3. Статична типізація означає, що типи змінних відомі під час компіляції. Це зменшує кількість помилок у runtime, покращує продуктивність і робить код більш передбачуваним.
4. Імутабельність означає, що значення не можна змінити після створення. Вона робить код безпечнішим, простішим для розуміння і запобігає неочікуваним побічним ефектам.
5. Move semantics означають передачу володіння значенням замість копіювання. Borrowing rules дозволяють або багато читачів, або одного писача, що гарантує безпеку памʼяті без GC.
6. Traits визначають спільну поведінку типів у Rust. Вони схожі на інтерфейси, але підтримують default-реалізації і використовуються для статичного та динамічного dispatch.
7. Lifetimes описують, як довго посилання є валідними. Вони запобігають використанню висячих (dangling) посилань під час компіляції.
8. Макроси — це механізм генерації коду під час компіляції. Вони дозволяють зменшити дублювання коду і реалізувати можливості, недоступні звичайним функціям.
9. &String — це посилання на тип String, а &str — на зріз рядка. &str є fat pointer (вказівник + довжина), а звичайні посилання є thin pointers (тільки адреса).
10. Статичний dispatch визначається під час компіляції і є швидшим. Динамічний dispatch визначається під час виконання через trait objects і дає більшу гнучкість.
